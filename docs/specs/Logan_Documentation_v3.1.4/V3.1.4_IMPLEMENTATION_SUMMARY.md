# Logan Intelligence — V3.1.4 Implementation Summary
**Version:** 3.1.4
*New in V3.1.4 (2026-08-06/07). Records the full BATCH-1 through BATCH-5 implementation pass authorized in
one continuous session, following 12 owner decisions (OD-001 through OD-012). Read alongside
`18_SESSION_LOG.md`'s 2026-08-06 entry and `23_CURRENT_IMPLEMENTATION_STATE.md`, which is authoritative on
current state — this file is the narrative record of what changed and why, batch by batch.*

---

## Scope

V3.1.4 was scoped as BATCH-1 (scoring/policy correctness) through BATCH-5 (mobile accessibility, quality,
Atmosphere integration), explicitly excluding: auth, Postgres persistence, multi-user migration, live
receptors, notifications, WebSockets, trained ML, source-reliability calibration, broad domain expansion,
and TriggerEvent/OpportunityLifecycle runtime code. Execution was continuous and autonomous once
authorized, with local commits only — no push, merge, deploy, or external publication.

---

## BATCH-1: Scoring and policy correctness

1. **`MentalModel.confidence` severed from `ConclusionConfidence` (ADR-015).** `confidence_score` now
   derives from `EvidenceTrust.trust_score` plus a contradiction penalty only — no Mental Model blend.
2. **`community_momentum` removed from ranking entirely (ADR-034).** No `dimensions.community_momentum *
   0.02` term in the rank formula; `global_importance = confidence.confidence_score` only (was a 50/50
   blend with momentum). This fixed a pre-existing conflict the prior session's
   `V3.1.3_IMPLEMENTATION_SUMMARY.md` had flagged but explicitly left unresolved.
3. **`priority_score` renamed to `internal_rank_score`, made genuinely internal-only (ADR-029).**
   `backend/app/logan_feed.py`'s public response now exposes an ordinal `rank: int` (1-indexed) instead of
   any score; mobile consumers migrated to `rank`, fixing a latent unit bug in `Vessel`'s prominence
   calculation (`item.priority_score / 100` on a field that was never 0–100) along the way.
4. **Not implemented, by design:** `hit_quality_score`/`user_value_score`. No accepted ADR or spec defines
   a deterministic split of the unified score into objective/personalized components — inventing one was
   explicitly out of scope. Documented as a deferred item, not silently dropped.

## BATCH-2: Contract completeness and tooling

1. **`ActiveContext.user_id`** added as a required field, threaded through `ActiveContextBuilder.build()`
   and the orchestrator.
2. **`decision_trace` populated** across every layer that produces a decision. The `contradicting` field on
   world-model events and the `contradicts` branch in reasoning remain documented-unreachable: no valid
   deterministic contradiction rule exists without inventing per-domain semantic comparison (prohibited);
   reserved and tested rather than built, per the instruction's own escape valve for genuinely undefined
   behavior.
3. **Fatigue/cooldown wired for real** — `FATIGUE_WINDOW`/`FATIGUE_LIMIT`/`COOLDOWN_WINDOW` (previously
   unwired constants) now drive actual expiration logic in `prioritization/engine.py`.
4. **Domain fields typed as the `Domain` Literal throughout**, replacing bare `str` in several contracts
   and engines.
5. **Full per-layer unit test coverage** — every previously-untested `logan_core` layer gained a dedicated
   test file. Test count: 95 `logan_core` tests + 8 `backend` tests, up from 40.
6. **Python tooling**: root `pyproject.toml` (Black/Ruff/mypy), dev-only deps. 17 mypy findings across both
   packages fixed with genuine type narrowing (exported Literal aliases, explicit annotations before
   if/elif chains) rather than suppressions, except 3 documented suppressions for a known mypy limitation
   on default-arg-capture lambdas. Two real (if runtime-benign) bugs caught this way: an `Optional[tuple]`
   ternary-indexing pattern in `world_model/model.py` and an analogous one in `prioritization/engine.py`.
7. **Mobile tooling**: ESLint flat config (`eslint-config-expo`) + Prettier. ~97 findings from
   React-Compiler-readiness rules determined to be near-100% false positives against this codebase's
   classic Animated API and fetch-on-mount patterns; disabled with documented rationale.
8. **CI**: `.github/workflows/ci.yml`, 3 jobs (`logan_core`, `backend`, `mobile`).

## BATCH-4: Real API and mobile migration

1. **`/v1/opportunities`**: replaced the old static-fixture route with a thin adapter over the real
   `logan_core` pipeline (`backend/app/opportunities.py`). `schema_version` metadata added;
   `internal_rank_score` never serializes (ADR-029); category filter preserved for compatibility.
   `_run_feed_pipeline()` extracted in `logan_feed.py` so this route and the now-`deprecated=True`
   `/v1/demo/feed` share one computation instead of duplicating it.
2. **Mobile migration**: the home screen (`app/index.tsx`) — the only primary-navigation screen on a
   `/v1/demo/*` route — now calls `/v1/opportunities`. `field-legacy.tsx`, `demo.tsx`, and `classic.tsx`
   stayed on their existing demo/legacy endpoints; they're preserved historical screens (ADR-023/026/027),
   not primary navigation.
3. **Opportunity Card consolidation**: the two near-duplicate card components merged into one canonical
   `OpportunityCard` (`DeliveredItem`-based, used by every current-generation screen). The old
   static-fixture card renamed `LegacyOpportunityCard`, kept only for `classic.tsx`.
4. **Environment-based API config**: `constants/config.ts`'s hardcoded LAN IP replaced with
   `EXPO_PUBLIC_API_BASE_URL` (Expo SDK 54 inlines this at build time automatically), falling back to the
   same dev IP so local `expo start` keeps working with zero config. `.env.example` added.

## BATCH-5: Accessibility, quality, Atmosphere

1. **Reduced motion**: `hooks/useReducedMotion.ts` (AccessibilityInfo-based, live-updating) wired into
   every ambient animation in AttentionField, Vessel, LoganCore, and OpportunityNode — continuous
   drift/breath/pulse loops freeze at rest, one-shot decorative ripples are skipped, user-triggered
   transitions (disclosure, focus) shorten rather than disappear. The Atmosphere/Skia layer uses
   Reanimated's own `useReducedMotion()` to freeze its shared drift clock.
2. **Accessibility**: labels/hints/roles/states added to every interactive element reached this pass —
   Vessel's disclosure tap, the home screen's menu and legacy-screen list, OpportunityNode's focus tap, and
   the button/input pairs across `ask.tsx`, `memory.tsx`, `demo.tsx`, `classic.tsx`. `PressableScale`
   defaults `accessibilityRole="button"`.
3. **Centralized fetch + loading/empty/timeout/retry/error states**: `lib/apiClient.ts`'s `fetchJson()`
   replaces ad hoc `fetch()` calls with a timeout, bounded retry, and `AbortSignal`-based cancellation,
   returning a typed `ApiResult` instead of throwing. The home screen now has five distinct, individually
   accessible states, with Retry/Refresh actions on timeout/error/empty.
4. **This repository's first Jest/RNTL test suite**: `jest-expo` preset,
   `@testing-library/react-native@13` (pinned below v14 — its new `test-renderer` peer dependency isn't
   what `jest-expo@54` ships). 19 tests: 8 for `apiClient`'s timeout/retry/abort/error paths, 3 for
   `useReducedMotion`'s live sync, 5 for the home screen's state transitions, 3 for the new Atmosphere
   layer's performance cap. CI's `jest` step, previously a no-op placeholder, now runs for real.
5. **Design tokens on the flagship screen**: exact-value magic numbers in `index.tsx` and `Vessel.tsx`
   replaced with the existing `spacing`/`radius`/`type` tokens — no visual change where a token already
   matched, nothing else touched.
6. **Atmosphere integration**: resolves ADR-028's open item. `AttentionAtmosphere.tsx` is a subordinate
   background layer for the live Attention Field — rendered behind the Vessels, `pointerEvents="none"`,
   deliberately narrower than the Sprint 1 preview (drops its 130 particles and fixed demo-entity clouds,
   both built to visualize "everything unresolved," the opposite job of a screen where every Vessel is
   already resolved). What's kept: a capped handful of soft color regions at real items' actual layout
   positions/colors (`MAX_CLOUDS = 4`, regardless of feed size — "connected to real feed state" without
   growing render cost with the feed), two haze blobs tinted from the top-ranked item, and a static
   fine-grain texture.
